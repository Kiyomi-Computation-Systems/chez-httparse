* chez-httparse

(CI badge goes here)

An HTTP/1.x parser for Chez Scheme, built as a byte-level state machine and
measured against [[https://github.com/nodejs/llhttp][llhttp]]'s own conformance corpus — not by re-implementing
its tests, but by replaying llhttp's *recorded traces* and comparing byte for
byte, at every chunk size.

#+begin_quote
✨ *AI Disclosure:* LLMs are used extensively in the planning and development of this project.
#+end_quote

*Status: v0.1 released; everything since on =main=.* Request and response
parsing, strict and lenient: *all 253* HTTP fixtures in llhttp's corpus, at
every chunk size from 1 to the input length. The 21 URL fixtures are a
separate parser, deferred to its own milestone and already vendored and
counted. See [[file:docs/conformance.org][docs/conformance.org]].

* What it is

- *A state machine, not a reader.* You feed it bytes; it calls you back. It
  keeps no buffer of its own, copies no spans, and allocates nothing in
  proportion to the input — a 10 KB body costs what a 10-byte one does.
- *Resumable by construction.* A token, header or body split across any
  number of feeds parses identically to one whole buffer. That is what the
  corpus replay at every chunk size actually tests.
- *Generated and committed.* =src/generated/httparse-message.sls= is emitted
  from =src/httparse/grammar.sls= and checked in, so what ships is reviewable
  as a diff and loadable without running a generator. A reference
  interpreter runs beside it over every fixture and must agree.
- *Pure Scheme.* No C, no FFI. The only dependency is the state-machine
  generator's runtime library.

* Using it

#+begin_src scheme
(import (generated httparse-message)
        (byte-machine runtime))

(define parser
  (make-parser
   httparse-message-machine
   (list
    ;; The one callback that ANSWERS: nothing in the bytes says whether a
    ;; request or a response is coming, and the embedder always knows.
    (list 'on-message-type (lambda (p ctx) 'request))

    ;; A span callback gets bounds into YOUR bytevector. Nothing is copied
    ;; and nothing is retained -- take what you need before returning.
    (list 'on-method-data
          (lambda (p ctx bv from to) (remember-method bv from to) callback-continue))
    (list 'on-header-field-data
          (lambda (p ctx bv from to) (remember-field bv from to) callback-continue))

    ;; ... the remaining callbacks. Every declared one must be bound: a
    ;; binding list with a hole is refused when the parser is made, not
    ;; quietly ignored.
    )
   #f))

(let ((r (parser-feed! parser chunk 0 (bytevector-length chunk))))
  (case (parser-result-status r)
    ((need-input) 'feed-more)
    ((error) (parser-error-reason (parser-result-error r)))
    (else (parser-result-status r))))
#+end_src

* Requirements

- Chez Scheme 10.4.1 or newer (=scheme=, =chez= and =chezscheme= are all
  probed; Petite is rejected)
- CMake 3.26 or newer (4.3.3 is what has actually been exercised)

The CMake-layer specifications run with no Scheme installed, via the
=no-scheme= preset. The optional live-llhttp differential additionally needs
Node and a C toolchain; it is off unless you ask for it.

* Building and testing

Run =make= (or =make help=) for the full target list. The main entries:

| =make build=    | configure and build the development preset      |
| =make dev=      | build, then run the harness self-tests          |
| =make test=     | build, then run the pull-request selection      |
| =make test-all= | build, then run the complete selection          |
| =make clean=    | remove all build trees                          |

Every target is a thin wrapper over checked-in CMake presets, so
=cmake --preset dev= and =ctest --preset pr= work identically everywhere,
including on Windows where =make= is not in the base install.

To run the parser against a live llhttp on generated input, see
[[file:docs/conformance.org][docs/conformance.org]].
